# 智能决策优化设计

> 状态：已确认方向，待按实施计划分阶段落地
> 目标场景：A 股日频波段、人工确认下单
> 核心原则：规则守底线、模型做排序、组合层做取舍、LLM 做解释

## 1. 背景与问题

现有智能决策已经聚合股票池、S1/S2/S3 信号、策略共振、热点、主线、基本面、估值、市场状态、持仓与风控，并能生成 BUY/SELL/HOLD 清单。当前主要问题不是缺少更多输入，而是缺少可验证的学习闭环：

1. 综合分主要由固定加减分组成，权重没有根据历史结果校准。
2. 历史归因只看次日涨跌，无法衡量波段持有期、回撤和交易成本。
3. 指定历史决策日时，部分服务仍可能读取当前简报、当前持仓或最新字段，不能作为可信回放。
4. 决策、人工采纳、成交和事后结果没有形成结构化关联。
5. 建议仓位以单票静态上限为主，没有统一处理相关性、行业暴露和已有持仓。
6. LLM 当前负责总结，缺少来源约束、结构化事件和反方质询，但也不应获得绕过硬风控的权限。

## 2. 目标与非目标

### 2.1 目标

- 任意历史交易日均能基于当时可见数据稳定回放。
- 每条建议可追溯到数据截止时间、特征、规则版本、模型版本和风险裁决。
- 用 1/3/5/10/20 个交易日结果持续校准候选排序和可执行阈值。
- 从单票独立评分升级为组合级仓位建议。
- 支持旧规则与新评分影子对比、快速回滚。
- LLM 输出可验证、可降级，只做解释和信息结构化。

### 2.2 非目标

- 不做券商直连和无人值守自动交易。
- 第一阶段不引入深度学习、在线强化学习或实时流式特征平台。
- 不让 LLM 直接生成交易数值、覆盖硬风控或修改落库事实。
- 不以单次回测收益作为模型上线依据。

## 3. 目标决策链路

```text
时点化数据快照
  -> 数据质量门禁
  -> 硬规则过滤
  -> 特征构建
  -> 收益/下行风险/置信度评分
  -> 市场状态融合
  -> 组合约束与仓位优化
  -> BUY/HOLD/SELL/AVOID
  -> 人工确认与成交
  -> 多周期结果归因
  -> 权重校准与影子评估
```

硬规则包括 ST、上市天数、流动性、数据过期、基本面硬门槛、总仓位/单票/行业上限和止损。模型只能在通过硬规则的候选中排序，不能解除规则拦截。

## 4. 数据模型

### 4.1 decision_run

一次决策运行的不可变元数据：

- `id`、`run_no`、`action_date`、`as_of_time`
- `group_name`、`mode`：LIVE/REPLAY/SHADOW
- `rule_version`、`model_version`、`feature_version`
- `data_level`、`data_cutoff_json`、`config_snapshot_json`
- `status`、`message`、开始/结束时间

同一交易日可有多次运行，但只有显式发布的运行成为当天主版本。读取历史时优先按已发布版本，不以最后一次覆盖前一次。

### 4.2 decision_feature_snapshot

每个运行、每只候选一条快照，保存决策当时实际使用的特征，而不是事后重新查询：

- 身份：`run_id`、`code`、`feature_version`
- 技术：趋势、动量、波动、成交量、相对强弱、策略信号
- 结构：共振数、热点源数、主线匹配、行业
- 基本面与估值：数值、报告期、数据发布日期、缺失标记
- 市场：市场状态、仓位系数、宽度、量能、情绪
- 持仓与风险：当前权重、行业权重、止损距离、相关性摘要
- `feature_json`：保留完整扩展特征；核心检索字段单独建列

特征必须带可见时间。财报按公告/可用日期纳入，不能只按报告期判断。

### 4.3 decision_outcome

结果表按 `action_id` 或 `run_id + code` 唯一关联：

- 1/3/5/10/20 交易日收益和相对沪深 300 超额收益
- 期间最大有利变动 MFE、最大不利变动 MAE
- 是否触及建议止损/止盈、首次触发日期
- 理论成交成本后收益
- 是否采纳、实际成交价/仓位、滑点、实际盈亏
- 结果完整度与最后计算时间

### 4.4 现有 daily_action

`daily_action` 继续作为面向用户的发布清单。新增 `run_id`、`rank_no`、`confidence`、`uncertainty`、`decision_status`，完整特征和实验数据不继续堆入该表。

## 5. 时点一致性与回放

所有参与决策的服务增加 `DecisionContext`：

- `actionDate`
- `asOfTime`
- `mode`
- `runNo`
- `dataPolicy`

LIVE 默认使用最近已收盘交易日的数据；盘中运行必须明确标记盘中数据。REPLAY 只能查询 `trade_date <= actionDate` 且 `available_at <= asOfTime` 的记录。当前无法提供可见时间的数据源先标为低可信，不进入模型训练。

回放验收采用两层校验：相同快照应生成相同特征哈希；相同规则/模型/配置版本应生成相同排序和动作。

## 6. 智能评分

### 6.1 第一版：可校准线性评分

第一版不增加 Java ML 运行时。将现有加减分拆成命名特征，离线用时间序列样本拟合正则化逻辑回归或受约束线性权重，导出 JSON 权重，由 Java 评分器加载。

分别输出：

- `returnProbability`：未来 5 日取得正超额收益的概率
- `expectedExcessReturn`：预期 5 日超额收益
- `downsideRisk`：未来 5 日出现显著 MAE 的概率
- `confidence`：样本量、数据质量和校准结果形成的可信度
- `uncertainty`：缺失、分布漂移或模型分歧形成的不确定性

统一效用分：

```text
utility = expectedExcessReturn
        - lambdaRisk * downsideRisk
        - estimatedCost
        - concentrationPenalty
```

### 6.2 市场状态融合

进攻、均衡、防守状态使用不同权重和阈值，但市场状态本身必须来自当日快照。样本不足时只调整阈值和仓位，不训练独立小模型。

### 6.3 可执行判定

可执行不再只看总分阈值，同时满足：

- 全部硬规则通过
- 数据质量不是 RED
- `confidence` 达标且 `uncertainty` 未超限
- 预期收益覆盖交易成本与风险预算
- 组合加入后不突破风险约束

## 7. 组合级决策

组合层接收排序后的候选、当前持仓和风险预算，输出目标权重与差额订单。第一版采用确定性启发式优化，不引入复杂求解器：

1. 用 ATR/历史波动率计算风险等权基础仓位。
2. 按效用分调整权重。
3. 扣除已有持仓，得到增量仓位。
4. 依次约束总仓位、单票、行业、相关性和最小交易单位。
5. 现金不足时按边际效用降序分配。

下单前单票风险必须按“原持仓市值 + 新订单金额”计算；SELL 侧同时考虑止损、趋势破坏、机会成本和组合再平衡。

## 8. LLM 边界

LLM 只承担：

- 把已同步新闻结构化为事件、方向、时效、相关标的和证据引用。
- 对规则/模型结果生成用户可读解释。
- 输出反方理由和需要人工核对的未知项。
- 回答“为什么入选/为什么被拦截/什么条件会改变结论”。

LLM 输出使用严格 JSON Schema，所有股票代码必须在输入集合内，所有事实必须绑定输入记录 ID。解析失败、超时或无 Key 时回退规则解释，不影响数值决策。

## 9. 评估与上线

### 9.1 离线指标

- Top 10% 候选 5 日超额收益、胜率与收益回撤比
- Brier Score、概率分桶校准误差
- 含成本收益、Sortino、最大回撤、换手率
- MFE/MAE、止损覆盖率、行业集中度
- 相对当前规则引擎的增量提升

### 9.2 上线门槛

- 时间序列 walk-forward 样本外评估，不使用随机切分。
- 至少覆盖一个完整牛熊/震荡区间；数据不足时不宣称泛化能力。
- Challenger 影子运行至少 20 个交易日。
- 风控违规为 0；核心数据缺失时能自动降级。
- 新版本未达到门槛时保留旧规则为 Champion。

## 10. 可观测性与安全

- 每条决策展示规则版本、模型版本、数据截止时间和降级原因。
- 监控特征缺失率、数据过期率、候选覆盖率、概率漂移和行业暴露。
- 运行完成后快照不可修改；重新运行生成新版本。
- 训练产物带数据区间、特征版本、指标和文件哈希。
- 支持配置开关一键关闭模型评分，回退现有规则引擎。

## 11. 实施顺序

1. P0：可信回放、运行/特征快照、风险修正。
2. P1：多周期 outcome 与人工采纳反馈。
3. P2：可校准评分和 Champion/Challenger。
4. P3：组合级仓位与调仓建议。
5. P4：LLM 事件抽取、解释与反方质询。
