# 回测实验历史设计

## 1. 问题

滚动样本外评估已经返回完整配置、成本、窗口结果和行情指纹，但结果只存在于当前页面内。刷新后无法回看，也无法确认两次实验是否使用了相同配置和行情输入。

## 2. 方案

- 每次滚动评估成功后自动保存，不增加容易遗漏的手动“保存”步骤。
- 新增 `backtest_experiment`，摘要字段用于历史列表和对比，完整请求与响应使用 JSON 快照保存。
- 保存的是后端实际采用的窗口、成本、初始资金、实际行情日期和 S1/S2/S3 可执行参数快照，不保存带默认值空缺的原始请求。
- 列表、详情和删除全部按当前 Sa-Token 登录用户过滤；不存在和无权访问统一返回“回测实验不存在”。
- 历史详情可以恢复页面参数和策略参数快照并复跑；复跑不受系统默认参数后续变更影响，且产生一条新记录，旧记录保持不可变。
- 页面最多选择两条历史实验并排比较策略参数、窗口参数、样本外区间、成本假设、核心绩效和数据指纹。

## 3. API

- `GET /api/backtest/experiments?limit=20`：返回当前用户最近实验摘要。
- `GET /api/backtest/experiments/{id}`：返回请求和结果快照。
- `DELETE /api/backtest/experiments/{id}`：逻辑删除当前用户实验。
- `POST /api/backtest/rolling-evaluate`：保持原路径，响应新增 `experimentId`，成功后自动留档。

## 4. 数据模型

`backtest_experiment` 保存用户、标的、策略参数、基准、窗口参数、实际日期、样本外日期、成本假设、核心绩效、数据指纹、请求 JSON、结果 JSON 和审计时间。列表查询只选择摘要列，不读取或返回 JSON 大字段；详情按主键和用户读取后解析为明确 DTO。

## 5. 边界

- 本次不提供实验改名、标签、分享和跨用户可见性。
- 历史记录不可编辑；删除使用逻辑删除。
- JSON 是当次结果快照，不替代可查询的摘要字段。
- 旧实验没有策略参数快照时按当前默认值运行；快照策略 ID 与所选策略不一致时明确拒绝。
- 数据库只生成迁移脚本，不自动执行 NAS 或线上升级。

## 6. 成功标准

- 成功评估自动生成当前用户实验记录并返回实验 ID。
- 其他用户不能查看或删除该实验。
- 历史详情可以恢复有效配置并按当时的可执行策略参数再次运行。
- 桌面和 390px 均可查看、复跑和删除历史记录，宽表只在自身区域滚动。
- 后端全量测试、前端全量测试、生产构建和差异检查通过。
