# 持仓导入体验设计

## 目标

把组合页的持仓导入从盲粘贴文本改成可检查、可修正、可重试的批量录入流程，同时保留从 Excel 或券商表格直接粘贴的效率。

## 交互

- 弹窗明确显示目标组合，并说明导入只会新增或更新同代码持仓，不会删除其他持仓。
- 用户可以选择、拖入或直接粘贴一张 PNG/JPEG/WebP 券商截图；识别期间锁定编辑和关闭操作。
- 截图识别结果进入同一份可编辑预览，低置信度、证券无法精确匹配、数量异常和重复证券逐行标出。
- 粘贴区支持 Tab、逗号、中文逗号和空格分隔，支持带“证券/数量/成本价”表头。
- 粘贴后立即生成可编辑预览；证券、数量、成本价可逐格修正，也可新增或删除行。
- 导入前阻止空证券、非正整数数量、非正数成本价和重复证券。
- 后端返回部分失败时保留弹窗，成功行标记为已导入，失败行展示完整原因；再次提交只重试未成功行。
- 桌面端使用紧凑表格，移动端切换为纵向记录，底部操作区保持可见且按钮不溢出。

## 边界

- 沿用现有 `/api/portfolio/{id}/import` 接口及“同代码更新”语义。
- 新增 `/api/portfolio/{id}/import/image/preview` 预览接口；接口校验组合归属，仅识别和校验，不落库。
- 图片仅在请求内传给已配置的视觉模型，不保存文件、不记录图片或模型原文；限制为单张且不超过 8 MB。
- 不增加全量覆盖模式，避免用户未确认删除已有持仓。
- 不在前端或模型侧猜测证券代码，服务端按代码或完整名称精确匹配股票库。

## 验收

- 三列数据可直接粘贴并预览，带表头时不会把表头当作持仓。
- 截图可通过选择、拖放或粘贴识别；无法确认的字段保留在预览中供用户修正。
- 本地错误在提交前逐行展示；部分服务端失败可原位修正并单独重试。
- `390x844` 与桌面视口下内容完整，无按钮、输入框或错误文案重叠。
