# Apex 策略实验室实施报告

## 交付内容

- 新增 `POST /api/backtest/rolling-evaluate`，支持固定训练窗和扩展训练窗。
- 支持训练日、测试日、步长、基准、初始资金和四项成本的单次实验配置。
- 返回逐窗口样本内外收益、年化、夏普、回撤、基准、超额和成交数。
- 返回样本外复合收益、基准复合、复合超额、正收益窗口率、胜基准率、整体夏普、最差回撤和覆盖率。
- 回测引擎改为收盘生成信号、次日开盘成交，并隔离未来行情。
- 次日开盘价缺失时明确拒绝实验，不再回退到当日收盘价；基准首日同样要求真实开盘价。
- 历史行情使用不可变前缀视图，隔离未来数据的同时避免逐日复制整段序列。
- 策略实验室页面增加集中参数区、汇总指标和逐窗口明细，保留其他回测工作流。
- 滚动结果回显策略参数、成交模型、复权口径、实际覆盖日期和 SHA-256 执行数据指纹；指纹覆盖 OHLCV 与逐日采用的涨跌停比例。
- 新实验使用 `NEXT_OPEN_V4`，在次日开盘成交语义上补充金额与费用的精确十进制计算；摘要独立保存成交语义版本和行情复权口径，既有实验保留原版本，缺失字段不做猜测性回填，在对比区明确显示未知口径。
- 每次成功实验自动保存当前用户的完整请求和结果快照，支持历史查看、删除、两条对比和按原配置复跑；结构化策略配置包含逻辑版本，明确携带旧版本的复跑请求会在行情读取前拒绝，避免静默改用新规则。
- S1/S2/S3 的可执行参数在评估开始时冻结，参数快照包含显式策略逻辑版本；历史复跑不会因系统默认参数变化而漂移，切换策略后也不会误带旧快照，策略规则升级后新旧结果也不会进入同一配置指纹。缺少逻辑版本的旧实验仍可查看和对比，但前后端会阻止其被当作精确复跑；用户可按当前规则新建实验。
- 实验摘要独立保存实际策略参数、窗口参数、样本外区间和四项成本；两条对比明确展示这些口径，避免把不同实验条件误认为可直接比较。
- 初始资金从隐藏默认值改为可见实验参数，并写入评估响应和历史摘要；结果元数据与两条对比会显示实际资金，旧实验缺失时明确标为未知。
- 回测页默认使用截至本地当天的最近三年区间，选股页批量回测使用最近两年区间；固定结束日期不再导致新行情被静默遗漏，闰日按目标年份月末回退。
- 普通、批量、策略对比、组合、参数扫描、旧 walk-forward 和滚动评估统一严格解析日期；非法日期、倒置区间和未来结束日均在行情 I/O 前按任务级错误拒绝。
- 普通回测在读取成本前校验请求、策略和六位证券代码，并对实际执行日线逐根校验日期顺序、前复权来源、OHLC 关系和成交量。
- 基准比较只接受系统登记的指数，并把策略、个股持有和基准持有统一裁到策略任务的实际首尾日期；实际区间覆盖不完整时拒绝比较，行情查询由四次收敛为两次。
- 初始资金控件与后端统一支持最小 `0.01` 和两位小数，查看历史实验后不会因前端最小值更大而夹断合法资金。
- 结果区直接展示响应冻结的数据区间、窗口、初始资金和四项成本，不再依赖运行后可继续编辑的控件表达历史口径。
- 实验列表只查询摘要字段，不加载 `request_json` 和 `result_json` 两列大快照；详情仍按需读取完整 JSON。
- 回测任务、成交、净值、派生分析、导出和策略榜按当前登录用户隔离。
- 历史批量和组合回测按开始日读取截止日不晚于开始日的股票池快照，缺失时明确失败。
- 组合回测按分位向下截断单标的初始资金，舍入余数保留为组合现金，传入各回测引擎的资金总额不会超过组合本金。
- 组合代码在行情查询前完成归一化、过滤和保序去重，同一证券的不同代码格式不再形成虚假分散仓位。
- 单票、批量、策略对比、组合、参数扫描、旧 walk-forward 和滚动实验都在任务开始时冻结一次默认成本；同一任务的候选、标的和样本内外不会因运行中配置变化使用不同成本。
- 批量回测对归一化后的唯一六位代码应用数量上限，全无效输入明确失败；批量、策略对比、组合和参数扫描只把业务失败写入单项结果，数据库或程序异常向上抛出，批量和策略对比的真实 Spring 事务代理回滚已有自动化覆盖。
- 普通回测任务保存四项成本、`NEXT_OPEN_V4` 成交语义、`QFQ` 复权口径和实际行情指纹；策略对比开始前冻结 S1/S2/S3 逻辑版本与参数，并让任务共享不可碰撞批次 ID、策略集合和配置指纹。策略榜先校验单批次的代码、实际区间、资金、成本、成交模型、复权口径和行情指纹完全一致，再只聚合最新同策略版本及参数、同成交口径、同资金及同成本的配对批次群；旧任务、不完整批次和异口径批次自动排除，页面同步展示冻结版本及参数、资金、成本和配置指纹。
- 股票池快照、默认自选候选、按批次和按日期查询均按当前登录用户隔离。
- 股票池拒绝未来截止日；早于今天的快照只允许从截止日前的本地市场日线重建，禁止使用当前自选或手工代码回填，并标记为 `RECONSTRUCTED_AS_OF`。
- 股票池批次使用不可碰撞标识，决策流程按本次刷新批次读取，避免并发刷新后误读全局最新批次。
- 启动期 `MarketSchemaBootstrap` 幂等覆盖 SQL 32-39 对应结构；关键 DDL 失败会阻止应用启动和健康检查。
- 自选股和兼容持仓表的唯一键改为包含 `user_id`，不同用户可保存同一证券。
- 定时同步、决策和自选导入后的异步预热显式绑定 Apex 用户上下文，不再依赖无登录线程读取私有资产。
- 组合、模拟账户和账户风控服务在缺少用户上下文时直接拒绝请求，私有资产查询不再省略 `user_id` 后退化为全局读取。
- Bot HMAC 客户端固定绑定一个外部用户和一个 Apex 用户；问答、工具和盘中主动告警均先校验绑定账户仍存在、已启用且已初始化，主动告警只扫描该绑定用户。
- 旧 walk-forward 的样本外评估保留训练历史用于指标预热，并从样本外首日独立起算资金。
- 回测拒绝非正初始资金，行情缓存同时校验数量、请求区间边界和前复权来源，涨跌停按主板、主板 ST、创业板/科创板和北交所区分。
- 窗口末遇一字跌停无法卖出或最后一日刚买入时保留未平仓头寸并按收盘市值计价，不再同日买卖；结果和前端明细显式展示期末未平仓数量与市值。
- 最大回撤从窗口初始资金开始计量，首个样本外交易日开盘建仓后的当日亏损不再被遗漏。
- 研究行情逐根校验日期顺序、OHLC 正值与区间关系、非负成交量；异常数据在实验保存前明确拒绝。
- 窗口模式、窗口大小、初始资金和最终成本快照在行情查询前完成校验，非法请求不会触发行情同步；引擎入口也统一拒绝空成本、负费率和超过 5% 的成本。
- 未来结束日会在行情 I/O 前拒绝；显式零成交量日不执行挂单、不生成新信号、不做窗口末强平，持仓仅按收盘价计值。
- 标的必须规范化为六位证券代码，基准必须是系统登记的指数代码；`000001` 等深市个股不能再通过直接 API 被误作指数基准。
- 查看旧实验详情和历史对比时，缺失的成交模型或复权口径均明确显示为未知。
- 组合回测的每条有效腿和沪深 300 基准都在任何任务数据落库前校验请求区间完整覆盖、东财前复权来源、日期顺序、OHLC 关系和非负成交量；少于两条合格组合腿或基准异常时整项失败。
- 组合任务保存冻结策略参数、四项成本、`NEXT_OPEN_V4`、`QFQ` 和组合 SHA-256 行情指纹；指纹按成分代码覆盖全部成功组合腿及沪深 300 基准，任一腿或基准 K 线修订都会改变审计结果。
- 单票详情、单票回测、策略对比、组合、参数扫描和基准对比在发起新请求前统一清理互斥结果及旧图表实例，并以各自加载状态拒绝重复请求，避免异步响应覆盖当前结果。
- 任务详情使用独立成功边界：核心详情失败才终止展示，月度收益或压力测试失败只清空对应附加区域；新回测会同步加载压力测试，基准成交详情失败也不再阻断已成功的比较曲线。
- 成交期望按已实现盈亏扣除买入与卖出手续费后的净收益总和直接除以平仓笔数，只在最终结果舍入；新回测和基准比较会立即回显该指标，不再把毛价差或中间舍入误差标为“期望/笔”。

## 运行要求

前端使用 Vite 8，需要 Node 20 或更高版本。本次使用 Node 24.19.0 完成测试和构建；本机默认 Node 18 会在 `node:util.styleText` 处失败。

数据库升级由后端启动时的 `MarketSchemaBootstrap` 幂等完成，覆盖 `apex-be/docs/sql/32` 至 `39` 对应结构；独立 SQL 文件保留用于审计和手工排障。若迁移失败，应用会启动失败而不会带着缺失结构通过健康检查。本次未部署 NAS，也未直接操作线上数据库。

## 未纳入范围

因子数据版本、滚动参数寻优、多资产组合优化、分钟级撮合和券商实盘适配留待后续阶段。旧 `backtest_job` 不做猜测性审计回填，也不会进入新的配对策略榜；部署 SQL 39 并产生完整策略对比批次后榜单才会出现可比较样本。Bot 当前是一组 HMAC 凭证固定绑定一个外部用户和一个 Apex 用户；未来支持多用户客户端时需要引入正式绑定表，不能按组合名或模型猜测身份。历史 MARKET 股票池来自当前本地行情缓存的事后重建，不等于权威的当时全市场成分；历史 ST 涨跌停仍使用当前证券状态，指纹能识别该状态变化，但不能还原历史戴帽/摘帽日期。待引入带生效日期的上市退市、成分、基本面和戴帽/摘帽数据后，才能提供严格 PIT 回放。
