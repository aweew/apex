# 组合交易记录代码评审

## 1. 评审结论

本次实现符合设计目标，未发现需要阻止交付的 Critical、Major 或 Minor 问题。统一交易流水按登录用户隔离，组合持仓写入与流水生成处于同一事务，Bot 重试具有业务幂等保护，交易查询没有进入股票详情共享缓存。

## 2. 核心检查

### 用户隔离

- 交易写入的 `user_id` 只取自 `ApexUserContext`，不接受请求传值。
- 分页和 K 线标记查询都固定附加当前 `user_id` 条件。
- 组合变更先经过 `requirePortfolio` 校验组合归属，不能跨用户写入。

### 事务与幂等

- Web 组合、真实持仓镜像和 Bot 导入都在持仓事务内生成交易流水；流水失败会回滚持仓变化。
- Bot 使用 `requestId:code` 作为来源引用，并由数据库唯一索引兜底。
- 相同请求重试不会重复记账；相同请求号对应不同数量变化时抛出业务异常并回滚。
- Bot 全量持仓由全删全建改为差异应用，未变化持仓不会生成伪买卖记录。

### 数据口径

- 数量增加记为 `BUY`，数量减少记为 `SELL`，并区分建仓、加仓、减仓和清仓。
- 用户或 Bot 没有提供成交价时，记录使用行情快照或最近收盘价，并明确标记为估算。
- 卖后最高和最低只统计成交日之后的日线，避免把卖出前的当日高低点计入卖后表现。
- 组合名称和归属人采用成交时快照，组合后续改名或删除不影响历史记录解释。

### 前端与安全

- 交易页提供组合、代码、方向、来源筛选，桌面表格和移动卡片分别布局。
- 日、周、月 K 线按周期聚合同周期同方向记录，并保留全部明细供提示框展示。
- K 线提示框对组合名和归属人进行 HTML 转义。
- 市场标签复用现有 `SecurityMarketBadge`，代码和股票名称保持现有页面语义。

## 4. 保留边界

- 功能上线前只有持仓状态，没有可靠成交事实，因此不倒推历史交易。
- 估算价格仅用于缺少实际成交价时的复盘参考，界面会明确显示“估算”。
- 卖后最高和最低基于日线，不提供分钟级成交后路径。
- 当前浏览器没有 Apex 登录态，尚未完成已登录桌面和移动端的视觉验收；静态布局测试和生产构建不能替代该验收。
