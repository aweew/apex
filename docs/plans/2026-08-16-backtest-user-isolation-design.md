# 回测任务用户隔离设计

## 问题

Apex 已采用私有邀请制并要求个人资产完全隔离，但 `backtest_job` 没有用户归属。任务列表、详情、成交、净值、月度收益、压力测试、成交期望、导出和策略绩效榜都可能跨用户读取或聚合。

## 设计

- `backtest_job` 增加非空 `user_id`，普通回测和组合回测写入当前 Sa-Token 登录用户。
- 任务列表和策略绩效榜在数据库查询阶段按当前用户过滤。
- 所有通过任务 ID 读取的数据先校验任务属于当前用户，再读取成交或净值子表。
- 不区分“任务不存在”和“任务属于其他用户”，统一抛出 `回测任务不存在`，避免暴露其他用户的任务编号。
- 子表继续通过 `job_id` 关联，不重复存储 `user_id`，归属边界由任务表统一维护。
- 新增独立迁移，不修改已部署迁移；存量任务迁给 `apex_user_profile` 中编号最小的管理员。

## 非目标

- 本阶段不改变策略算法、回测指标或页面交互。
- 本阶段不引入角色共享、公开实验或管理员跨用户查看能力。
- 本阶段不持久化滚动实验的每个窗口，实验审计能力在归属边界稳定后单独设计。

## 验证

- 新建任务和组合任务带当前 `user_id`。
- 列表与绩效榜查询包含当前 `user_id` 条件。
- 不属于当前用户的任务不能读取详情、成交、净值及其派生分析。
- 回测聚焦测试、后端全量测试和 `git diff --check` 通过。
