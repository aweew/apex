# Apex 可维护选股策略设计

> 状态：待确认
> 目标：在股票筛选页维护、复制并运行用户自己的选股策略；系统提供可解释的常用模板，不把模板宣传成已验证盈利策略。

## 1. 问题

当前股票筛选支持 PE、PB、流通市值、涨跌幅、量比、连续上涨、RS20 和 ATR 等临时条件，但条件不能命名、保存、版本化或复用。实时截面、历史日线和分时条件也没有统一的数据时点说明，容易出现界面能配置、实际数据却不满足口径的问题。

本次需要把“筛选条件”升级为可维护的“选股策略/战法”，同时保留现有自由筛选能力。

## 2. 目标与边界

### 2.1 目标

- 用户可新建、编辑、复制、启停、排序和删除自己的策略。
- 系统通过只读代码注册表提供常用模板，用户复制后才能修改，避免跨用户共享资产。
- 选股时可选择一个策略直接运行，也可将策略条件载入表单后临时调整。
- 每个结果展示命中的关键指标、数据截止时间和缺失数据说明。
- 实时策略采用“截面粗筛 -> 历史条件 -> 分时复核”三阶段执行，控制外部请求量。

### 2.2 非目标

- 第一阶段不做多策略 AND/OR/SCORE 组合；一条策略内部的规则默认全部为 AND。
- 第一阶段不做自动下单、收益承诺或自动把回测最优参数发布为实盘策略。
- 没有历史分钟数据前，不宣称分时规则已经通过历史回测。
- 不复制商业系统的私有规则；系统模板只采用公开、常见且可解释的筛选思想。

## 3. 示例策略口径

用户示例初始化为“主板强势承接”模板：

| 条件 | 默认值 | 数据来源与口径 |
| --- | --- | --- |
| 市场范围 | 沪深主板 | 排除科创板、创业板、北交所、基金和 ST |
| 当日换手率 | 5% 到 10% | 东财实时截面 `f8` |
| 近 20 个交易日涨停 | 至少 1 次 | `bar_daily`，主板非 ST 按涨幅不低于 9.5% 识别 |
| 当日涨幅 | 3% 到 5% | 东财实时截面 `f3` |
| 量比 | 大于 1 | 东财实时截面 `f10`，不再混用现有“日成交量/20 日均量”近似值 |
| 总市值 | 50 亿到 200 亿 | 东财实时截面 `f20` |
| 分时均线承接 | 稳定在均价线上方 | 09:35 后截至当前，不低于均价的分钟点占比至少 95%，当前价不低于均价，连续跌破不超过 3 分钟 |

“全天”在盘中只能表示“截至当前”。收盘后运行时才代表完整交易日。页面必须同时显示运行时间和分时点数量，不能把盘中结果伪装成收盘结果。

## 4. 方案比较

### 方案 A：保存整个筛选请求 JSON

改动最小，但字段校验、条件编辑、索引查询和后续扩展困难，不利于展示每条规则的命中原因，不采用。

### 方案 B：策略表 + 规则明细表

策略保存名称、说明、来源、运行模式和版本；每条规则以明确的规则类型、操作符、上下限和参数保存。便于校验、复制、排序和扩展，推荐。

### 方案 C：通用表达式或脚本引擎

灵活度最高，但会引入表达式安全、类型校验、调试和版本兼容问题，超出当前个人研究工具的需要，不采用。

## 5. 数据模型

### 5.1 `screener_strategy`

- `id`、`user_id`：用户资产隔离，`user_id` 非空。
- `name`、`description`：策略名称和说明。
- `source_type`：`USER` / `TEMPLATE_COPY`。
- `template_key`：复制来源的系统模板稳定标识，可空。
- `run_mode`：`REALTIME` / `CLOSE`。
- `enabled`、`sort_no`、`version_no`。
- 创建、更新时间和逻辑删除字段。

### 5.2 `screener_strategy_rule`

- `id`、`strategy_id`、`rule_type`、`operator_code`。
- `min_value`、`max_value`、`int_value`、`text_value`、`bool_value`。
- `lookback_days`、`tolerance_value`：历史窗口和容错阈值。
- `sort_no`、创建、更新时间和逻辑删除字段。

Java 使用字段明确的普通 DTO/Entity 和带 `code`、`desc` 的枚举，不使用 `Map<String, Object>` 承载规则。新增 MySQL 表及所有字段都写数据库 `COMMENT`。

系统模板不落为共享用户资产。后端以字段明确的只读模板 DTO 注册，列表接口合并“系统模板 + 当前用户策略”；复制模板时才写入当前用户的策略和规则表。

## 6. 规则目录

第一阶段支持：

- 市场板块、排除 ST。
- PE、PB、总市值、流通市值。
- 当日涨跌幅、当日换手率、实时量比。
- 近 N 日涨跌幅、近 N 日涨停次数、连续上涨天数。
- RS20、ATR14/现价。
- 分时价格在均价线上方占比、当前价相对均价、连续跌破分钟数。

每种规则定义支持的数据模式、数值单位、默认范围和数据来源。保存时校验上下限、窗口范围和互斥条件；必要数据缺失时按“未通过”处理，并在结果摘要中统计缺失数量。

## 7. 执行链路

```text
加载策略和版本
  -> 校验用户归属与规则
  -> 拉取全 A 实时截面
  -> 市场/涨幅/换手/量比/市值粗筛
  -> 批量加载候选最近 N 日日线
  -> 计算涨停次数、RS20、ATR 等历史条件
  -> 对剩余候选限流并发拉取分时
  -> 校验均价线承接
  -> 返回结果、命中指标、数据时间与缺失摘要
```

- 实时截面复用东财 `clist` 能力，字段至少包含代码、名称、价格、涨幅、换手率、量比、总/流通市值和更新时间。
- 分时只对粗筛后的候选执行，默认并发 4，增加短时缓存，避免重复运行触发数据源限流。
- 任何必需数据过期或缺失都不得静默放行。
- 现有自由筛选继续走原入口；策略运行使用独立请求 DTO，避免继续膨胀 `ScreenerReq`。

## 8. 页面设计

- 股票筛选页增加“自由筛选 / 策略选股”分段切换。
- 策略选股顶部使用策略选择器；常用操作放在菜单中：新建、复制、编辑、停用、删除。
- 选中策略后直接展示紧凑规则清单，不把每条规则做成卡片。
- “运行策略”是唯一主操作；“载入自由筛选”用于临时调整，不覆盖已保存版本。
- 桌面结果表和移动结果卡增加“命中依据”，展示换手、量比、市值、近 20 日涨停次数和分时承接比例。
- 页面显示数据状态：实时截面时间、日线截止日、分时截止分钟、缺失或失败数量。

## 9. 系统模板

首批模板只覆盖现有数据能可靠计算的常用思路：

1. 主板强势承接：本设计中的用户示例。
2. 放量突破：价格突破、实时量比和成交量共同确认，参考现有 S3 思路。
3. 相对强势趋势：RS20、连续上涨和 ATR 约束。
4. 低位放量：价格分位、量比和反弹幅度组合，需要补价格分位规则。
5. 中盘估值筛选：PE、PB、总市值组合，仅作为候选过滤，不命名为“价值优选”。

模板统一标记“常用模板，收益未经验证”。用户需要复制到自己的策略后才能修改。

## 10. 测试与验收

- 用户只能读取和修改自己的策略；系统模板只读。
- 示例策略可正确识别主板、50 亿到 200 亿、换手 5% 到 10%、涨幅 3% 到 5%、量比大于 1、20 日内至少一次涨停。
- 分时规则覆盖 95% 临界值、当前价跌破、连续跌破超过 3 分钟和数据缺失。
- 外部截面或分时接口失败时返回明确降级信息，不产生伪命中。
- 前后端单元测试、完整前端测试、后端构建和 Node 20 生产构建通过。
- 桌面和 390px 移动端策略维护、运行和结果页面无横向溢出。

## 11. 分期

### P0：可用闭环

策略 CRUD、系统模板复制、单策略 AND 运行、示例策略、实时/历史/分时三阶段筛选、命中依据和数据时点。

### P1：研究闭环

保存运行快照和结果、策略版本对比、纯日线规则历史回放、模板回测状态。

### P2：组合策略

多策略 AND/OR/SCORE、策略评分、定时运行和命中通知。只有通过样本外验证的版本才允许标记为“已验证”。
