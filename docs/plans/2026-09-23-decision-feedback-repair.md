# 智能决策触发、发布与结果反馈修复

## 已核实的问题

- 决策页只有同步中心链接，没有直接生成入口，也没有任务进度和完成后结果刷新。
- 2026-09-23 午间生产记录已经发布买入候选 101 条，全部 executable_hint=0，风险标记集中为市场广度不足及行业逆主线。主清单只显示可执行项，候选折叠且缺少具体拦截原因，造成没有结果的观感。
- today 只查正式结果，最新失败或未发布尝试不可见。共享任务把所有未抛异常的用户运行算作成功。
- 生产 InnoDB 最近死锁发生于北京时间 2026-09-23 06:55；两个用户首次插入当日 daily_action 时在 idx_daily_action_date 的 supremum gap 上互相等待插入意向锁，回滚其中一个用户事务。数据库隔离级别为 REPEATABLE-READ，日期和用户复合索引均存在。

## 实施方案与完成情况

1. 决策页提供管理员“生成今日决策”、所有用户“刷新结果”，复用共享后台任务及既有权限。
2. 串行轮询任务，展示真实进度；完成后自动加载结果，读取失败持续提示并重试。离开页面停止轮询，丢弃启动前的旧状态响应。
3. 首屏显示最近运行状态、候选数量、风控通过数、主要拦截原因、结果日期及行情日期；没有可执行项时展开待跟踪候选并逐项展示原因。
4. today.latestRun 返回当前用户、所选日期最新 LIVE 尝试，独立于已发布清单。未发布返回 generated=false，共享摘要分别统计已发布、未发布和失败。
5. 仅将发布事务改为 READ_COMMITTED，保留用户运行记录行锁、整批替换原子性与失败回滚，针对已证实的跨用户日期间隙锁冲突修复。现有调用链无外层事务覆盖该配置。

- Java 增加最新状态、已发布清单保留、共享摘要及 Spring 事务代理配置/回滚测试。
- 遵循用户未经允许不编译的约定，未运行 Java 测试、前后端构建或部署。

## 后续验收

获准编译部署后运行上述 Java 聚焦测试，部署并验证：管理员进入“工作台 → 智能决策 → 生成今日决策”，进度更新、结果自动加载、候选阻塞原因可见；普通用户可查看状态与刷新，但不能启动共享任务。用独立测试数据库复现两个用户首次发布的并发场景，验证均提交且同用户结果只有一个正式版本。
