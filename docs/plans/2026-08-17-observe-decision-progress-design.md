# 观察池自动决策进度设计

> 状态：已确认方案，按测试驱动实施

## 问题

观察池的“自动决策”直接调用同步接口 `/api/observe/auto-decide`。决策会扫描共享全 A 股票池并分批读取日线，前端在最长 120 秒内只能显示“决策中…”，无法知道任务仍在运行、当前阶段或完成比例。

现有 `sync_job` 已注册 `DECISION` 后台任务，具备异步执行、状态查询、日志和重复运行保护，但决策执行目前只有开始和完成两个状态，中间仍是 `0% -> 100%`。

## 方案

- 观察池改用 `/api/sync/jobs` 启动 `DECISION`，请求立即返回任务 ID。
- 决策服务上报市场准备、组合快照、股票池、策略扫描、共振、估值、风控和观察池写入等真实阶段。
- 信号服务按现有 40 只股票一批的扫描节奏回报完成数，映射到决策任务的整体进度。
- 观察池每秒查询任务状态，原地显示百分比、阶段、耗时和任务 ID，不强制跳转任务中心。
- 当前浏览器会话保存本次任务 ID，页面刷新后可继续跟踪；重复启动错误中的任务 ID 也可接回。
- 决策结果与旧同步接口保持兼容，任务运行后仍不允许中止，避免部分信号或观察项落库。

## 验收

- 点击后快速返回任务 ID，页面不再等待长 HTTP 请求。
- 全市场扫描期间百分比随批次推进，阶段文案可读。
- 成功后自动刷新观察池，失败时显示后端任务说明。
- 快速离开或刷新页面不终止后台任务，返回后可继续查看进度。
- 前后端专项测试、全量测试和生产构建通过。
