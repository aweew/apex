# 后台智能决策用户隔离设计

## 背景

`DECISION` 通过 `sync_job` 在线程池中异步执行，定时器也不在 HTTP 请求线程中运行。现有用户资产服务直接从 Sa-Token 请求上下文读取登录用户，因此后台任务缺少用户身份。与此同时，决策发布按日期全局替换 `decision_run` 和 `daily_action`，即使只给任务补用户上下文，不同用户的正式决策仍会互相覆盖。

## 目标

1. 手动智能决策由当前登录用户拥有，定时任务为每个启用用户分别创建。
2. 同一用户只能有一个进行中的智能决策，不同用户可以并行运行。
3. 用户只能查看自己的智能决策任务和结果，不能读取或操作其他用户的任务。
4. 行情同步任务继续保持全局共享和全局去重。
5. 后台线程显式绑定用户，任务结束或异常后必须清理，不能污染线程池复用的后续任务。
6. 在没有用户与通知通道绑定关系前，智能决策结果不得发送到全局 WeClaw 收件人。

## 方案

### 受控用户上下文

新增 Spring 管理的 `ApexUserContext`。请求线程优先使用 Sa-Token 登录用户；后台执行通过 `runAsUser(userId, task)` 显式绑定用户。绑定采用 `ThreadLocal`，并在 `finally` 中恢复上层值或清理，支持线程池复用和有限嵌套。

用户资产服务统一通过该上下文获取用户 ID。认证登录、邀请、管理员权限等只属于 HTTP 认证流程的代码继续直接使用 Sa-Token，避免后台身份被误用为认证操作。

### 任务所有权

`sync_job.user_id` 对共享任务为空，对 `DECISION` 必须有值。手动 `start` 从当前上下文取 owner；定时器调用内部 `startForUser`，请求 DTO 不暴露 `userId`。

智能决策的进行中去重条件为 `task_type + user_id + status`。共享任务仍按 `task_type + status` 全局去重。最近任务和总览返回全部共享任务及当前用户自己的智能决策；按 ID 查询和停止会校验智能决策 owner。

### 决策结果所有权

`decision_run.user_id` 和 `daily_action.user_id` 标记结果 owner。发布时只锁定、撤销和替换同一用户同一交易日的数据。今日决策、建议、历史、归因和回放只读取当前用户的运行与动作；通过 `run_id` 关联的特征、组合快照和归因记录沿用运行 owner。

旧的无 owner 数据不分配给任意管理员，迁移后保持 `NULL`，不进入任何用户的私有查询。

### 调度与通知

调度器查询启用用户 ID，并逐用户提交任务；单个用户提交失败只记录该用户，不影响其他用户。18:30 归因只处理市场数据和已有运行记录，可继续全局批量补算，但用户查询必须按运行 owner 过滤。

当前 WeClaw 只有一个全局 recipient，没有可信的用户绑定。为避免跨用户泄露，后台智能决策不再主动推送摘要；待未来建立 `user_id -> recipient` 显式绑定后再恢复逐用户推送。

## 兼容性

迁移只新增可空 owner 字段和索引，不执行数据迁移或部署。新代码写入用户私有记录时保证 owner 非空；共享同步任务保持 owner 为空。前端 API 结构不增加可伪造的 `userId`。
