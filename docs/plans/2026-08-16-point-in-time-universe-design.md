# 历史回测股票池时间点设计

## 问题

批量回测和组合回测未指定代码时直接读取最新股票池。历史区间因此会使用今天的入池结果，产生幸存者偏差和未来信息泄漏。`universe_snapshot.create_time` 只能说明快照何时计算，不能表达其数据截止日。

## 设计

- `universe_snapshot` 增加非空 `as_of_date`，明确快照只使用该日及以前的数据。
- 历史刷新使用请求中的 `asOfDate`；普通刷新记录当天日期。未来日期直接拒绝。
- 早于今天的刷新只允许 `scope=MARKET`，禁止用当前自选或手工 `codes` 回填过去。
- 历史 MARKET 候选由本地当前仍持有的 `bar_daily` 按截止日重建，并标记 `RECONSTRUCTED_AS_OF`。它能约束行情截止日，但不是权威的严格时点成分数据。
- 新增 `latestAsOf(date)`，只选择 `as_of_date <= date` 的最新批次。
- 批量和组合回测的隐式股票池改用回测开始日前可用的最新快照，避免把区间末已知的成分用于整个历史区间。
- 每个股票池批次归属当前登录用户；默认候选只读取该用户自选，按日期和按批次查询均带用户条件。
- 找不到历史快照时明确失败，禁止回退到当前股票池；显式传入 `codes` 的行为不变。
- 批次号使用 32 位随机标识，避免同一秒并发刷新共享批次号。
- 刷新后需要继续计算的流程按返回批次号读取，不再次依赖全局“最新批次”。

## 数据迁移

存量快照用 `DATE(create_time)` 回填 `as_of_date`，并归属给编号最小的管理员。生成日期不能证明更早的数据口径，因此不会把存量快照伪装成历史点位快照。

严格 PIT 股票池仍需要带生效日期的全市场证券状态、上市退市记录、ST 状态和历史基本面。当前重建模式不能消除本地行情覆盖范围带来的幸存者偏差，研究结论必须保留该限制。
