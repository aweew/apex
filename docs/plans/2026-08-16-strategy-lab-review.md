# Apex 策略实验室代码审查

## 结论

本次变更达到当前已登录用户的单标的日线研究场景代码交付标准，但不宣称具备严格 PIT 全市场成分回放。新增接口为加法式演进，旧 `/walk-forward` 保留；滚动评估结果能回显窗口、成本、策略参数、成交语义、复权口径、实际覆盖日期和行情数据指纹。

## 已解决问题

- P0：收盘信号不再按同日收盘成交，统一为下一交易日开盘执行。
- P0：策略每次只接收截至信号日的历史前缀，无法读取未来 K 线。
- P1：历史前缀改为不可变 O(1) 视图，避免长窗口逐日复制造成二次方级内存分配。
- P1：独立窗口末强制清算，扣除卖出滑点、佣金和印花税后再复合。
- P1：样本内和样本外统一成本及清算口径，年化收益衰减可比较。
- P1：整体夏普由各样本外窗口日收益拼接计算，窗口夏普均值单独保留。
- P1：基准必须精确覆盖样本外首尾；窗口超限、重叠、成本越界和资金非法均显式拒绝。
- P1：标的成交日和基准首日缺开盘价时明确失败，禁止回退到当日收盘价破坏次日开盘语义。
- P1：回测任务、子表读取、派生分析、导出和策略榜均按当前用户校验或过滤。
- P1：历史隐式股票池按回测开始日取快照，无历史快照时不再回退当前股票池；未来日期、当前自选和手工代码不能再伪造历史快照。
- P1：股票池快照写入和读取均按当前用户隔离，默认候选不会混入其他用户自选。
- P1：股票池批次改为不可碰撞标识，决策流程读取本次刷新批次，避免并发下混批或读错批次。
- P1：行情输入和逐日采用的涨跌停比例生成 SHA-256 指纹，可识别数据修订或当前 ST 制度变化造成的结果差异。
- P1：新实验摘要保存 `NEXT_OPEN_V4` 成交语义和 `QFQ` 复权口径；V4 使用精确十进制金额与费用计算，既有记录保留原版本，缺失字段在前端标为未知，不伪造历史版本。
- P1：S1/S2/S3 可执行参数随实验冻结，包含 S3 退出回溯路径；参数快照写入策略逻辑版本，历史复跑不再读取变更后的系统默认值，策略代码升级后的结果也不会沿用旧配置指纹。
- P1：策略接口要求显式逻辑版本，实验结构化配置同步保存该版本；明确携带过期或缺失版本的复跑请求在行情 I/O 前失败，前端也会阻止旧记录被误当作精确复跑。存量实验仍可查看和对比。
- P1：实验对比补齐实际策略参数、训练/样本外/步长、样本外统计区间和佣金/印花税/买卖滑点，避免不同口径结果被误判为可直接比较。
- P1：初始资金不再是页面隐藏默认值，新实验单独保存并在结果与对比中显示；服务拒绝保存缺失或非正的资金快照，旧记录保持未知。
- P1：结果元数据直接回显实际数据区间、窗口、资金和成本快照，运行后修改表单不会改变已展示结果的审计口径。
- P1：实验历史列表改为显式摘要列查询，不再为列表加载两列 `MEDIUMTEXT` JSON 快照。
- P1：实验历史加载失败、重复复跑和并发历史操作均有独立状态约束，失败不会继续展示旧结果。
- P1：旧 walk-forward 样本外窗口保留训练历史用于指标预热，不再把短样本外区间从索引 0 重新预热。
- P1：初始资金在服务入口和回测引擎双重校验，零值或负值不会进入收益率除法。
- P1：行情复用同时校验数量和请求区间边界，避免长但陈旧的缓存静默通过。
- P1：一字板成交限制按主板、主板 ST、创业板/科创板和北交所的适用比例判断。
- P1：启动 Bootstrap 幂等覆盖 SQL 32-38 对应结构，关键迁移失败会阻止应用健康启动。
- P1：自选股和兼容持仓唯一键包含用户 ID，第二个用户添加相同证券不再触发全局唯一键冲突。
- P1：定时同步、决策和自选导入预热绑定明确用户上下文，后台线程不再以无登录状态访问私有资产。
- P1：组合、模拟账户和账户风控服务缺少用户上下文时在访问 Mapper 前失败，私有资产操作不再退化为全局查询。
- P1：Bot HMAC 客户端固定绑定外部用户和 Apex 用户，未知外部用户和已禁用/未初始化的绑定账户会被拒绝；盘中告警只扫描绑定用户，避免单收件人通道泄露其他账户数据。
- P1：滚动实验行情只接受完整覆盖请求边界的前复权数据，截断、混合来源和新浪原始行情不会被静默保存。
- P1：窗口末一字跌停无法成交时保留未平仓头寸并按收盘价计值，不再伪造强平交易。
- P1：窗口最后一日刚成交的买单不再被同日收盘强平，保留期末头寸以遵守 T+1。
- P1：资金曲线最大回撤以初始资金为首个峰值，修正带预热窗口首日亏损被记为零回撤的问题。
- P1：滚动实验在落库前逐根校验日期、OHLC、成交量和复权来源，缺失或关系非法的行情不会静默进入指标。
- P1：窗口模式、窗口大小、初始资金和成本假设在行情 I/O 前校验，非法请求不再先查库或触发同步；回测引擎同时为所有调用路径统一约束成本范围。
- P1：未来结束日在行情 I/O 前明确拒绝；显式零成交量日会顺延挂单、禁止新信号和末日强平，只保留持仓市值标记。
- P2：旧实验缺少审计字段时，详情和两条对比均显示未知口径，不再留下空白元数据。
- P2：原四参数空序列回测兼容，内部参数错误使用业务异常。
- P2：前端滚动评估使用独立加载状态；390px 控件、指标、元数据换行和表格滚动范围有自动化契约测试。
- P1：标的代码和基准类型在行情 I/O 前校验；移除 `000001` 指数选项后，直接 API 也不能再把深市个股误作指数基准。
- P1：等权组合单腿资金向下截断到分，余数留作现金，所有回测腿的入金合计不再因四舍五入超过组合本金。
- P1：组合标的先归一化并保序去重，重复代码不能再被当作多个独立仓位；去重后不足两只会在行情 I/O 前拒绝。
- P1：回测页和选股批量回测的默认日期改为基于本地当天的三年/两年滚动区间，固定 `2026-08-01` 不再让研究范围随时间失效；闰日边界有确定性测试。
- P1：组合、参数扫描、旧 walk-forward、批量和策略对比均在任务级冻结默认成本，所有腿、候选和样本阶段共享同一个校验后的 8 位成本快照。
- P1：批量代码按归一化后的唯一标的应用上限，全无效列表明确拒绝；批量和策略对比只降级业务异常，系统异常向上抛出并由事务整体回滚。
- P1：普通回测和所有共享日期入口使用严格日期解析，非法日期、倒置区间和未来结束日不会再误报为行情不足；空请求、短代码、未知批量策略和共享资金错误在成本或行情读取前拒绝。
- P1：普通回测逐根验证前复权来源、日期顺序、OHLC 和成交量；旧来源或结构异常数据不会进入引擎。
- P1：基准比较只接受登记指数，并统一使用策略任务实际覆盖区间计算策略、个股持有和基准持有；基准或标的首尾覆盖不完整时事务回滚。
- P1：组合和参数扫描与批量、策略对比使用相同异常边界，只降级业务异常；系统异常原样上抛，批量和策略对比的 Spring 事务代理回滚已有测试证明。
- P1：策略对比开始前冻结 S1/S2/S3 参数，任务保存配对批次、策略集合、配置指纹、资金、四项成本、成交版本、复权口径和行情指纹；榜单先接纳策略齐全且批次内部审计维度一致的任务，再只聚合最新同参数、同成交口径、同资金及同成本的批次群。旧任务、不完整批次和口径漂移批次均被排除，响应与页面会回显榜单采用的资金和成本假设。
- P1：组合回测的每条有效腿和沪深 300 基准都在首条任务数据落库前校验完整区间、前复权来源、日期顺序、OHLC 和成交量；任一关键输入异常时不再留下部分任务。
- P1：组合任务保存冻结策略参数、四项成本、成交版本、复权口径和组合行情指纹；指纹覆盖全部成功组合腿及基准，基准数据修订不再绕过重现实验审计。
- P1：单票、策略对比、组合、参数扫描和基准比较统一清除互斥旧结果并阻止重复请求，较慢的旧响应不能再覆盖新的结果视图。
- P1：详情页把核心任务与月度收益、压力测试等附加分析分开结算；新回测也会同步加载压力测试，附加接口失败只收起对应区域，基准成交详情失败不影响已取得的比较曲线。
- P1：成交“期望/笔”改为扣除买卖双边手续费后的已实现净收益总和直接除以平仓笔数，只在最终结果舍入；新回测和基准比较会立即显示该值，与后端实际现金变化保持一致。

## 兼容与风险

- 标准回测的成交结果会因“次日开盘成交”而变化，这是纠正前视偏差后的预期行为。
- 旧 `/walk-forward` API 未删除，但页面不再把一次 70/30 切分作为主要验证入口。
- 当前停牌只识别数据中明确存在的零成交量日；若数据源直接省略停牌日，不额外补造交易日。盘口深度、成交量冲击、最低佣金、上市首日特殊涨跌幅规则、精确排队成交和分红税仍未模拟。
- 各样本外窗口独立起算，复合值用于研究比较，不代表一条连续实盘资金曲线。
- 当前浏览器没有已登录会话，登录后桌面和 390px 的真实数据页面仍需在可认证环境复验。
- 数据库结构会在新后端启动时自动迁移，包括新增的 SQL 39 回测任务审计字段，但本次没有部署 NAS 或操作线上数据库，不能把本地结果视为已部署能力。
- Bot 当前只支持一组 HMAC 凭证固定绑定一个外部用户和一个 Apex 用户；扩展到多用户客户端前需要正式绑定表。
- 历史 MARKET 快照标记为 `RECONSTRUCTED_AS_OF`：候选来自当前本地 `bar_daily` 对旧日的事后重建，仍可能遗漏后来退市或从未同步的证券，不能视为权威的当时全市场成分。
- 历史 ST 涨跌停仍读取当前 `stock_basic.st_flag`，在缺少带生效日期的证券状态数据时无法准确还原戴帽和摘帽前后的限制；指纹只记录本次实际采用的制度，不能补足历史状态。
- SQL 35-37 按设计不把旧决策、日志和策略信号分配给管理员；升级后这些 `user_id IS NULL` 的存量记录不会出现在新的用户隔离查询中。
- 旧 `backtest_job` 缺少配对与审计字段，无法恢复真实实验口径，因此保持不可比较并从新榜单排除；榜单需要部署 SQL 39 后新产生的完整策略对比批次。

## 审查结果

当前差异未发现阻断级代码回归。严格 PIT 全市场成分和历史 ST 制度仍受数据源限制；旧任务不会伪造审计口径，新策略榜只使用新产生的严格配对批次。后端完整测试 446/446、策略实验室与回测相关集中回归 140/140、前端完整测试 136/136 均通过；前端生产构建、OpenClaw Shell 语法检查和 `git diff --check` 均已通过。
